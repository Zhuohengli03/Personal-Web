## 问题

《Dark and Darker》里玩家市场的物品价格每小时都在波动。判断买卖时机，需要了解物品的通常价格、当前价格是否偏低，以及未来的变化趋势。游戏只提供当前挂单，没有历史价格，因此首先需要持续采集数据，建立自己的数据集。

## 决策

**先采集，后建模。** 前几周只做接入：每个物品一个 API 采集器，去重、批量写入 PostgreSQL；调度器在中断后能继续跑；连续三页没有新数据就自动停止。可靠的建模依赖干净、连续的价格序列。

**用配置管理物品。** 物品按类别（矿石、消耗品、装备、材料）写在 `items_config.json`，启用或停用物品无需修改 Python 代码；系统会自动发现新的 API 文件。物品清单变了，管道照样跑。

**滞后特征，严格只用过去。** 特征只用预测时刻已有的值（价格滞后、滚动均值、星期几）；流程会报告数据泄漏检查结果，并做特征筛选抑制过拟合——从 32 个特征中保留 15 个，避免未来信息进入训练数据、导致评估结果失真。

**集成，并把分歧展示出来。** 随机森林、极端随机树、梯度提升、四个线性模型、SVR、MLP 与 XGBoost 投票；预测阶段再融合 ARIMA 和统计基线。输出是带 95% 置信区间的 7 日路径和一句风险提示。区间变宽——比如预测的最后一天——提示预测的不确定性增加，需要谨慎判断交易时机。

## 结果

一套无人值守的采集与预测流程、一个按类别存储挂单的 PostgreSQL 库，以及每日的 7 日预测（趋势、风险等级、买卖建议）。截图展示的这一轮黄金矿石分析中：采集 6,164 条，集成 R² 0.995、无过拟合（交叉验证差 −0.011），输出提示为「价格呈下降趋势，考虑卖出——高风险」。仓库获得 6 次 GitHub 星标，并提供中英双语说明文档。接口、数据库、分析、调度四个模块的结构，也成为我后续数据项目的基础。
